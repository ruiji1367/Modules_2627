What is a thread?

  • A Thread is a class in C#.NET found in the System.Threading namespace, used to create and control threads — its properties and methods are already provided.
  • A thread is an independent execution unit containing a piece of code. When a process begins, the main thread is started.
  • All threads within a process share the same state and memory space, and communicate with each other to perform different tasks.

Main thread

The first thread performed in a process. Other threads created afterward are its child threads.

//Sample Main Thread
Thread basicThread = Thread.CurrentThread;
basicThread.Name = "Basic C# Thread";
Console.WriteLine("Current Thread: {0}", basicThread.Name);

Child thread

Created by writing a delegate, passing a callback method to it. ThreadStart defines the method that runs when the thread starts.

//Sample Child Thread
private void btnRunThread_Click(object sender, EventArgs e)
{
    ThreadStart delThread = new ThreadStart(ChildThreadMethod);
    Thread childThread = new Thread(delThread);
    Thread.CurrentThread.Name = "Main Thread";
    Console.WriteLine(Thread.CurrentThread.Name);
    childThread.Start();
}
//method
public void ChildThreadMethod()
{
    Console.WriteLine("Calling child thread");
}

Code walkthrough: controlling a thread's life cycle

This example starts a child thread, lets it run for a few seconds, then aborts it — showing Start(), Sleep(), and Abort() together.

private Thread _childThread;

private void btnCheck_Click(object sender, EventArgs e)
{
    ThreadStart delThreadObj = new ThreadStart(ThreadCycle);
    Console.WriteLine("Will Create Child Thread In Main Thread\u2026");
    _childThread = new Thread(delThreadObj);
    _childThread.Start();
    Thread.Sleep(3000); //3 seconds before aborting the thread.
    Console.WriteLine("Aborting Child Thread");
    _childThread.Abort();
}

public void ThreadCycle()
{
    try
    {
        Console.WriteLine("Thread starts here!");
        Console.WriteLine("Paused for 2 seconds: child thread");
        Console.Write("Countdown: ");
        for (int x = 2; x > 0; x--) {
            Console.Write(x + " ");
            Thread.Sleep(1000);
        }
        Console.WriteLine("\nChild thread resume");
        Console.WriteLine("WaitSleepJoin State: (Child Thread):" +
            (_childThread.ThreadState == ThreadState.WaitSleepJoin));
        Thread.Sleep(1000); //Thread sleep or pause for 1 second
        Console.WriteLine("Child Thread Done.");
    }
    catch (ThreadAbortException ex)
    {
        Console.WriteLine("Exception Message: " + ex.Message);
    }
    finally {
        Console.WriteLine("Finally Block the Thread!");
    }
}

TRY

The child thread does its work — sleeping (WaitSleepJoin) between countdown ticks. If Abort() is called on the main thread while this is running, execution here is interrupted.

CATCH (ThreadAbortException)

Abort() throws a ThreadAbortException inside the aborted thread. It can be caught here — but it is automatically re-thrown at the end of the catch block, so the thread still terminates.

FINALLY

Runs no matter what — whether the thread finished normally or was aborted — so cleanup code always executes before the thread reaches Stopped.

Multithreading & race conditions

Multithreading lets an application run more than one execution path at the same time. The CPU serves each thread for a time slice in round-robin fashion (Harwani, 2015, p. 438).

private Thread _childThread1, _childThread2, _childThread3;

private void btnStart_Click(object sender, EventArgs e)
{
    Console.WriteLine("--------");
    Console.WriteLine("Main Thread Running\u2026");
    ThreadStart delObjThread = new ThreadStart(Method1);

    _childThread1 = new Thread(delObjThread);
    _childThread1.Name = "Child Thread 1";
    _childThread2 = new Thread(delObjThread);
    _childThread2.Name = "Child Thread 2";

    _childThread3 = new Thread(new ThreadStart(Method2));
    _childThread3.Name = "Child Thread 3";

    _childThread1.Start();
    _childThread2.Start();
    _childThread3.Start();

    _childThread1.Join();
    _childThread2.Join();
    _childThread3.Join();
    Console.WriteLine("Value of x: " + x);
    Console.WriteLine("Value of y: " + y);
}
///Methods to be called in ThreadStart delegate
public void Method1(){
    Console.WriteLine(Thread.CurrentThread.Name + " running...");
    x++;
}
public void Method2(){
    Console.WriteLine(Thread.CurrentThread.Name + " running...");
    y++;
}

Why this is a race condition: _childThread1 and _childThread2 both run Method1, and both increment the same shared variable x at roughly the same time. Because neither thread's increment is synchronized with the other, the two updates to x can overlap — which is exactly what a race condition is: two threads accessing and manipulating the same resource simultaneously, with an outcome that depends on timing. Join() is used here only to make the main thread wait until all three child threads finish — it does not, by itself, protect x from being modified unsafely while they run.
